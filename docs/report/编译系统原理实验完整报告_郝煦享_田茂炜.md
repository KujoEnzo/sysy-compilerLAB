## 摘要

本实验以迭代阶乘程序为统一案例，观察 C 源程序从预处理、词法和语法分析，到 LLVM IR、汇编、目标文件及可执行文件的表示变化；进一步对 LLVM IR 执行 `mem2reg`，分析局部变量从内存槽提升为 SSA 值及循环 `phi` 节点的过程。在此基础上，实验分别实现调用 SysY 运行库的 C/SysY 兼容源程序、手写 LLVM IR 和手写 RISC-V 汇编，并将三条路线统一构建为 RV64GC/LP64D 静态可执行文件，在 `qemu-riscv64` 下进行对照测试。

实验结果表明：宿主机源程序、优化前后参考 IR 均通过 0、1、5、10、12 五组阶乘测试；RV64 源程序、手写 LLVM IR 和手写汇编三条路线共 15 次运行全部得到预期标准输出，退出码均为 0。`file`、`readelf` 与反汇编结果进一步确认目标文件的架构、ABI、调用序列、32 位整数运算、返回地址保存及栈对齐符合预定设计。实验同时区分标准输出与教师运行库写入标准错误的计时信息，避免将运行库信息误判为程序答案。

**关键词：** 编译阶段；抽象语法树；LLVM IR；SSA；mem2reg；RISC-V；SysY 运行库

## 4. 阶乘源程序与宿主机基准

核心阶乘函数采用迭代写法：循环变量从 2 开始，累乘值初始化为 1，当 `i <= n` 时更新结果并令 `i` 加 1。因此输入 0 或 1 时循环体不执行，函数直接返回 1。

```c
int fact(int n) {
    int i = 2;
    int result = 1;
    while (i <= n) {
        result = result * i;
        i = i + 1;
    }
    return result;
}
```

宿主机基准程序 `src/fact.c` 使用 `scanf` 和 `printf`。五组实际测试如下：

| 输入 | 预期输出 | 实际输出 | 退出码 |
| ---: | ---: | ---: | ---: |
| 0 | 1 | 1 | 0 |
| 1 | 1 | 1 | 0 |
| 5 | 120 | 120 | 0 |
| 10 | 3628800 | 3628800 | 0 |
| 12 | 479001600 | 479001600 | 0 |

结果保存在 `logs/a/fact-baseline.txt`，为后续 IR 和 RISC-V 路线提供行为基准。

## 5. 编译阶段与中间表示观察

### 5.1 GCC 外部编译阶段

实验依次执行：

```bash
gcc -E src/fact.c -o build/host/fact.i
gcc -S build/host/fact.i -o build/host/fact.s
gcc -c build/host/fact.s -o build/host/fact.o
gcc build/host/fact.o -o build/host/fact
```

`fact.i` 仍是 C 语言文本，但包含头文件展开及源位置标记；本次源文件 23 行，预处理文件 762 行。行数增加来自头文件和预处理信息，不表示已经生成更多机器指令。

`fact.o` 是 x86-64 可重定位 ELF，最终 `fact` 是动态链接的 x86-64 PIE 可执行文件。`nm` 显示目标文件定义了 `fact` 和 `main`，同时引用 `__isoc99_scanf`、`printf` 与 `__stack_chk_fail`。未定义符号表示需要在链接阶段解析，并不等同于编译失败。

### 5.2 宿主机汇编对应关系

未优化的 x86-64 汇编将参数 `n`、循环变量 `i` 和结果 `result` 分别放入栈槽。循环由比较、条件跳转、`imull` 和 `addl` 组成。初始化后先跳到条件检查，符合 `while` 的先判断语义。

`main` 还包含输入返回值检查和栈保护逻辑。入口从 `%fs:40` 读取保护值，退出前比较，异常时调用 `__stack_chk_fail`。这些代码属于编译器和 ABI 加入的保护机制，不是阶乘算法本身。证据见 `logs/a/host-fact-assembly.txt`、`logs/a/host-main-assembly.txt` 与 `logs/a/object-symbols.txt`。

### 5.3 Token 与 AST

Clang 的 token 输出表明，函数名被识别为 `identifier`，整数常量为 `numeric_constant`，`<=` 是单个 `lessequal` token。词法分析把字符流切分为带源位置的记号序列。

AST 中，`fact` 对应 `FunctionDecl`，参数对应 `ParmVarDecl`，函数体对应 `CompoundStmt`；循环为 `WhileStmt`，其条件和循环体中的运算由嵌套的 `BinaryOperator` 表示。变量读取外层出现 `ImplicitCastExpr <LValueToRValue>`，说明该 AST 除语法结构外还记录类型、声明引用和隐式转换等语义信息。证据见 `logs/a/tokens.txt` 与 `logs/a/fact-ast.txt`。

## 6. LLVM IR 与 SSA 优化

### 6.1 参考 LLVM IR

使用 Clang 生成 O0 参考 IR：

```bash
clang-15 -S -emit-llvm -O0 \
  -Xclang -disable-O0-optnone -fno-discard-value-names \
  src/fact.c -o build/ir/fact_O0.ll
llvm-as-15 build/ir/fact_O0.ll -o build/ir/fact_O0.bc
llvm-dis-15 build/ir/fact_O0.bc -o build/ir/fact_roundtrip.ll
```

参考 IR 的 `fact` 包含 `entry`、`while.cond`、`while.body`、`while.end` 四个基本块。参数和局部变量先由三个 `alloca i32` 建立内存槽，随后以 `load`、`store` 读写；`icmp sle i32` 表示有符号 `i <= n`，`br i1` 根据比较结果选择循环体或退出块。

### 6.2 mem2reg 对照

执行：

```bash
opt-15 -S -passes=mem2reg -verify-each \
  build/ir/fact_O0.ll -o build/ir/fact_ssa.ll
```

仅统计 `fact` 函数，优化前后结果为：

| 指令 | 优化前 | 优化后 |
| --- | ---: | ---: |
| `alloca` | 3 | 0 |
| `load` | 6 | 0 |
| `store` | 5 | 0 |
| `phi` | 0 | 2 |

优化后的循环条件块包含两个 `phi`：

```llvm
%i.0 = phi i32 [ 2, %entry ], [ %add, %while.body ]
%result.0 = phi i32 [ 1, %entry ], [ %mul, %while.body ]
```

首次由 `entry` 进入时选择初值 2 和 1；从循环体回边进入时选择本轮更新值。`phi` 按控制流前驱选择值，不是把多个候选值同时运算。优化前 IR 同样遵循 SSA 的值定义规则，只是源语言变量主要通过内存表示；`mem2reg` 将可提升的栈槽改写为直接 SSA 值。

优化前后参考 IR 程序在五组输入下均与宿主 C 程序输出一致、退出码为 0。该结果证明所列测试范围内行为保持一致，但不构成全部输入的形式化等价证明。

### 6.3 手写 LLVM IR

`ir/fact_hand.ll` 直接面向 `riscv64-unknown-linux-gnu`，使用两个 `phi i32` 表示循环变量和累乘结果：

```llvm
loop:
  %i = phi i32 [ 2, %entry ], [ %i.next, %body ]
  %result = phi i32 [ 1, %entry ], [ %result.next, %body ]
  %cond = icmp sle i32 %i, %n
  br i1 %cond, label %body, label %exit

body:
  %result.next = mul nsw i32 %result, %i
  %i.next = add nsw i32 %i, 1
  br label %loop
```

`main` 调用 `getint`、`fact`、`putint` 和 `putch(10)`。函数声明、定义及调用处的 `signext` 属性保持一致，用于表达 RV64 ABI 中 32 位有符号整数在 XLEN 寄存器中的扩展要求。该 IR 经过 `llvm-as` 解析、`opt -passes=verify` 验证和 `llc` 目标代码生成。

## 7. SysY 运行库处理

教师材料中的预编译 `libsysy_riscv.a` 经 `nm -u` 检查存在 `_impure_ptr` 未定义引用，表明它可能依赖 Newlib 环境。当前实验采用 `riscv64-linux-gnu-gcc` 与 glibc，因此不直接混用该预编译库，也不伪造 `_impure_ptr`。

实验保留教师原始归档，由教师提供的 `sylib.c` 重新构建 Linux 目标静态库：

```bash

  -mcmodel=medany -O0 -c vendor/lib/sylib.c \
  -o build/runtime/sylib_rv64_linux.o
```

重建对象引用 `printf`、`putchar`、`__isoc99_scanf` 和 `gettimeofday` 等 Linux libc 符号，不再引用 `_impure_ptr`。两份符号记录见 `logs/b/teacher-runtime.undefined-symbols.txt` 与 `logs/b/runtime-undefined-symbols.txt`。

## 8. 手写 RISC-V 汇编

### 8.1 阶乘函数

`asm/fact_hand.s` 中，`fact` 的参数和返回值均通过 `a0` 传递。该函数不调用其他函数，只使用调用者保存的 `t0`、`t1`，因此无需建立栈帧：

```asm
fact:
        li      t0, 2
        li      t1, 1
.Lfact_loop:
        blt     a0, t0, .Lfact_done
        mulw    t1, t1, t0
        addiw   t0, t0, 1
        j       .Lfact_loop
.Lfact_done:
        mv      a0, t1
        ret
```

`blt a0, t0` 将源程序条件等价改写为“若 `n < i` 则退出”。`mulw` 与 `addiw` 执行 32 位运算并将结果符号扩展到 XLEN，与 C/SysY `int` 的目标机表示一致。

### 8.2 main、返回地址与栈对齐

`main` 依次调用四个函数，属于非叶函数。每个 `call` 都会覆盖 `ra`，因此入口保存 `ra`，返回前恢复；栈指针一次减少 16 字节，满足调用边界的 16 字节对齐：

```asm
main:
        addi    sp, sp, -16
        sd      ra, 8(sp)
        call    getint
        call    fact
        call    putint
        li      a0, 10
        call    putch
        li      a0, 0
        ld      ra, 8(sp)
        addi    sp, sp, 16
        ret
```

`getint` 与 `fact` 的返回值直接留在 `a0` 中作为下一次调用的参数。函数没有使用 `s0` 至 `s11`，故无需额外保存被调用者保存寄存器。

### 8.3 伪指令、重定位与链接

汇编源文件使用 `li`、`mv`、`j`、`call` 和 `ret` 等伪指令。目标文件反汇编显示，小立即数和部分跳转采用 RVC 压缩编码；未链接目标文件中的 `call` 展开为带 `R_RISCV_CALL`、`R_RISCV_RELAX` 重定位的 `auipc`/`jalr` 组合。链接后符号被解析，链接器还可能执行指令松弛，因此目标文件与最终可执行文件需要分别观察。相关记录见 `logs/b/fact_hand_asm.object-disassembly.txt` 与 `logs/b/fact_hand_asm.linked-disassembly.txt`。

`file` 与 `readelf` 显示，`runtime_smoke`、`fact_source`、`fact_hand_ir`、`fact_hand_asm` 均为小端 ELF64 RISC-V 静态可执行文件，带 RVC 和 double-float ABI 标志。手写汇编程序入口地址为 `0x10560`，ELF flags 为 `0x5`。这确认三条路线进入相同的 RV64GC/LP64D 静态运行环境，而不是误用宿主机 x86-64 产物。

### 10.3 结果讨论

三种程序表示采用相同算法、接口、运行库、目标 ABI 和测试输入，实际输出一致，说明在已测试输入范围内，源程序的循环语义能够由手写 SSA IR 和手写 RV64 汇编正确表达。目标文件反汇编还表明汇编器正确处理了伪指令和调用重定位，最终 ELF 检查表明链接结果符合预定目标架构。

实验没有进行性能测量，不能据此断言手写 IR 或手写汇编比源程序更快；五组输入也不是形式化证明。负数、输入失败、13 及以上导致的 32 位溢出，以及浮点、数组和逻辑短路等语言特性不属于本次测试范围。

## 11. 复现方法

从课程渠道取得教师运行库，在 Ubuntu 中进入项目根目录，本地放置 `lib.tar.gz` 后执行。压缩包不随本轮修正版公开跟踪：

```bash
tar -tzf lib.tar.gz
mkdir -p vendor
tar -xzf lib.tar.gz -C vendor
make check-tools
make clean
make environment
make test
make inspect
sh tests/run_build_regressions.sh
sh tests/run_rv64_domain_tests.sh build/riscv64/fact_source \
  build/riscv64/fact_hand_ir build/riscv64/fact_hand_asm
```

随后检查：

- `logs/local/b/results.md`：本次重新生成的 15 次运行结果矩阵；原 `tests/results.md` 保留 B 的历史记录；
- `logs/a/`：编译阶段、token/AST、参考 IR 和 A 的 RV64 记录；
- `logs/local/b/fact_*`：本次测试的 stdout、stderr 与退出码；原 `logs/b/` 不覆盖；
- `logs/local/b/file-types.txt`、`fact_hand_asm.readelf.txt`：新生成的 ELF 与 ABI 信息；
- `logs/local/b/fact_hand_asm.*disassembly.txt`：新生成的目标文件及链接后反汇编；
- `logs/local/a-review/`：全部 13 个有效输入、三条路线共 39 次运行的原始记录。

本轮修正使冒烟测试在非零退出码时立即失败；`make clean` 只删除构建产物，不再删除日志。新记录统一放在忽略的本地目录，需要纳入报告时单独核对并归档，避免覆盖其他成员的证据。

默认使用 LLVM 15 工具名。若系统安装 LLVM 18，可显式覆盖：

```bash
make LLVM_AS=llvm-as-18 OPT=opt-18 LLC=llc-18 test inspect
```

## 12. 结论

本实验以阶乘程序贯通了源程序、预处理文本、token、AST、LLVM IR、汇编、目标文件和可执行文件。预处理仍保留源语言形态；AST 表示嵌套语法与语义关系；LLVM IR 以基本块、分支和 SSA 值表示控制流；`mem2reg` 将 `fact` 中三个可提升内存槽及其读写转换为两个循环 `phi` 和直接 SSA 值。

在 RV64 目标实验中，手写 LLVM IR 使用 `i32`、`icmp sle`、`phi` 和一致的 `signext` 属性表达源程序语义；手写汇编使用 `a0` 传递参数和返回值，以 `mulw/addiw` 保持 32 位整数运算，以有符号分支实现循环条件，并在非叶 `main` 中正确保存 `ra`、保持 16 字节栈对齐。运行库兼容性分析避免了 Newlib 预编译库与 glibc Linux 工具链的错误混用。

实际测试中，宿主程序和优化前后参考 IR 均通过五组测试；RV64 源程序、手写 IR 与手写汇编共 15 次运行全部通过，退出码均为 0，stdout 与期望值逐字节一致。结合 ELF、符号、重定位和反汇编证据，可以确认两位成员分工完成的前端观察、LLVM IR、运行库接入、RV64 汇编及统一测试已经形成一条完整且可复现的实验链路。
